Báo cáo thí nghiệm — C1 Cascade Filter

Phạm vi: H1 Phase 1a — ablation 3 cổng lọc pseudo-label (conf → ITM → xcons)
Đề tài: Cải tiến SelTDA trên A-OKVQA
Dataset / metric: A-OKVQA validation accuracy
Ngày báo cáo: 02/06/2026
Lưu ý phạm vi: Báo cáo này chỉ mô tả bước lọc cascade 3 gate (Contribution C1 — Phase 1a). Chưa bao gồm TS-1 (ngưỡng theo question type), CS-X (coreset), hay C2 closed-loop. Trong code/spec, ba gate được đánh số: Gate 1 = conf Gate 2 = ITM Gate 3 = xcons

Paper gốc: Khan et al., CVPR 2023 — self-train trên train.json + toàn bộ pseudo-QA (synthetic_data_raw.json), không qua filter_pseudo.py. Số published Tab.4 ≈ 60.01% (A-OKVQA val, synth:real 2:1); em replicate được 60.61% trên cùng setup local.

Chưa chạy trong batch này: Gate 3 (xcons) riêng lẻ, và full cascade C+I+X — đây là variant dự kiến tốt nhất theo protocol H1.

Kết luận sơ bộ (Phase 1a — partial):
  • Gate 1 (conf) đóng góp nhiều nhất trong các run đã có (+3.06%).
  • Gate 2 (ITM) một mình không đủ — thậm chí tệ hơn baseline (−3.49%).
  • C+I (gate 1 + gate 2) tốt hơn conf-only (+0.78%), cho thấy ITM bổ sung sau conf.
  • So với paper gốc (60.61%): Gate 1 (+0.44%) và C+I (+1.22%) đã vượt SelTDA gốc — đây là claim chính của contribution.
  • Synthetic thô = paper gốc; mọi variant lọc bằng conf đều cao hơn paper.

2. Bối cảnh

2.1 Pipeline SelTDA gốc

  1. Train teacher VQG trên dữ liệu có nhãn.
  2. Sinh pseudo-QA từ ảnh không nhãn → synthetic_data_raw.json.
  3. Self-train student VQA trên train.json + synthetic.

Khan et al. (CVPR 2023) ghi nhận ~30% pseudo-QA noisy. Code gốc không lọc chất lượng nội dung — chỉ parse regex khi generate.

2.2 Contribution C1 — Phase 1a (H1)

Chèn bước filter_pseudo.py giữa generate và train. Ba cổng chạy cascade tuần tự: sample fail bất kỳ cổng đang bật → loại.

Tên trong log Tên trong code Tín hiệu Vai trò
Gate 1 conf Mean log-probability teacher trên chuỗi Q+A Loại output teacher không tự tin
Gate 2 itm CLIP cosine similarity (ảnh ↔ "Q? A.") Loại Q/A không grounded trên ảnh
Gate 3 xcons Student pretrained trả lời vs pseudo-answer Loại sample mâu thuẫn cross-consistency

Ngưỡng: quantile keep_top = 0.75 trên từng gate đang bật (giữ top 75% theo score). Thứ tự cascade: conf → itm → xcons (filtering/gate_registry.py).

2.3 Ràng buộc thiết kế

Không sửa train_vqa.py / loss / eval. So sánh công bằng: cùng config train, khác duy nhất file synthetic và gate nào được bật khi lọc.

4. Quy trình từng bước

B0 Chuẩn bị

bash dataset.sh
python convert_aokvqa.py --config configs/aokvqa.yaml

Tải COCO, A-OKVQA, checkpoint teacher (checkpoint_04.pth) và student pretrained (checkpoint_09.pth dùng cho gate xcons).

B1 Sinh synthetic (một lần, dùng chung)

python generate_questions.py \
  --config configs/generate_questions_aokvqa.yaml \
  --overrides \
    output_folder=datasets/aokvqa \
    pretrained=cache/teacher_weights/checkpoint_04.pth \
    questions_per_image=2 \
    output_annotations_name=synthetic_data_raw.json

Lý do: Tạo pool raw chứa cả sample tốt và nhiễu — input cho mọi variant lọc và baseline unfiltered.

B2 Lọc theo từng variant gate

Chạy filter_pseudo.py với configs/filter_pseudo.yaml, bật/tắt từng gate qua gates.<name>.enabled. Mỗi gate bật dùng keep_top: 0.75.

Variant conf itm xcons Output synthetic
Raw (unfiltered) off off off synthetic_data_raw.json (không qua filter)
Gate 1 only (C) on off off file lọc chỉ conf → train weights1
Gate 2 only (I) off on off file lọc chỉ ITM → train weights2
Gate 1 + Gate 2 (C+I) on on off cascade conf→ITM → train weights12
Chưa chạy: C+I+X on on on full cascade — variant #7 trong protocol H1

Ví dụ lọc chỉ Gate 1 (conf):

python filter_pseudo.py \
  --config configs/filter_pseudo.yaml \
  --overrides \
    input=datasets/aokvqa/synthetic_data_raw.json \
    output=datasets/aokvqa/synthetic_data_c.json \
    gates.itm.enabled=false \
    gates.xcons.enabled=false

Lý do cascade tuần tự: Gate 3 (xcons) tốn GPU nhất (forward BLIP từng sample); chạy sau conf+ITM giảm số lần forward. Ablation bật/tắt từng gate tạo ma trận 2³ = 8 biến thể (protocol H1 §3.4).

Chi tiết từng gate

  • Gate 1 — conf: \(s_{conf}\) = mean log-prob teacher trên chuỗi đã sinh; chuẩn hóa min-max pool; giữ top quantile.
  • Gate 2 — ITM: \(s_{itm}\) = cosine CLIP(image, "question answer"); rescale về [0,1]; giữ top quantile. Format "Q? A." giúp phân biệt answer chung chung (vd. "yes") không khớp câu hỏi cụ thể.
  • Gate 3 — xcons: Student pretrained (chưa train synthetic) trả lời Q; match với pseudo-answer (exact + SBERT cosine, lấy max). Chưa có kết quả train trong batch này.

B3 Train student

python -m torch.distributed.run --nproc_per_node=1 train_vqa.py \
  --output_dir=cache/self_trained_weights_<variant> \
  --config configs/aokvqa.yaml \
  --overrides \
    "train_files=[train,<synthetic_file>]" \
    truncate_train_dataset_to=34000 \
    wandb=false \
    use_validation_set_as_test_set=true

Baseline trainset-only: train_files=[train], không truncate.

B4 Evaluate

python -m torch.distributed.run --nproc_per_node=1 train_vqa.py \
  --output_dir=cache/evals \
  --evaluate \
  --config configs/aokvqa.yaml \
  --overrides \
    pretrained=cache/self_trained_weights_<variant>/checkpoint_09.pth \
    use_validation_set_as_test_set=true \
    wandb=false

5. Phân tích kết quả

5.1 Trainset only (57.99%)

Mức sàn không self-training. Là baseline thấp nhất trong bảng — mọi cấu hình có synthetic (trừ ITM-only) đều vượt.

5.2 Trainset + synthetic (raw) — Paper gốc (60.61%)

Đây là baseline SelTDA gốc (Khan et al., CVPR 2023): train trên dữ liệu thật + toàn bộ pseudo-QA chưa lọc, không qua bất kỳ gate nào. Tương đương variant 0b trong protocol H1. Mọi cải tiến C1 (conf, ITM, xcons) đều so sánh trực tiếp với dòng này — không so với “trainset only”.

Paper báo cáo ~60.01% (Tab.4); em replicate 60.61% trên setup local (cùng synth:real 2:1). ~30% pseudo-QA nhiễu vẫn vào training → đây là điểm xuất phát mà contribution nhằm vượt qua.

5.3 Gate 1 only — conf (61.05%, +0.44% vs paper)

Lọc theo độ tự tin teacher là tín hiệu mạnh nhất trong batch hiện tại. Loại sample teacher "bị ép" sinh ra → tập synthetic sạch hơn dù có thể nhỏ hơn raw. Đã vượt paper gốc dù chỉ bật một gate.

5.4 Gate 2 only — ITM (54.50%, −3.49%)

CLIP matching một mình không đủ và có thể chọn subset lệch: answer ngắn ("yes/no") khó phân biệt polarity; ITM không thay thế được conf. Đây là bằng chứng ablation quan trọng — không thể chỉ dùng Gate 2.

5.5 Gate 1 + Gate 2 — C+I (61.83%, +1.22% vs paper)

Sau khi conf lọc nhiễu rõ ràng, ITM bổ sung thêm ràng buộc grounded (Q+A khớp ảnh) → +0.78% so với conf-only, +1.22% so với paper gốc SelTDA. Đây là kết quả tốt nhất trong các run đã có, nhưng chưa phải full cascade — Gate 3 (xcons) chưa được train/eval.

8. Bước tiếp theo

  1. Hoàn thành variant C+I+X (full 3 gate) và các variant còn lại (X, C+X, I+X).
  2. Chạy 3 seeds, báo cáo mean ± std (protocol yêu cầu).
  3. Random-subsample control cùng N với filtered (IDEA-04).
  4. Sau khi H1 Phase 1a xong mới chuyển sang Phase 1b (TS-1), 1c (CS-X) — ngoài phạm vi báo cáo này.
